# 概念

AI 游戏开发包括开发时使用 AI 辅助编写代码，以及在运行时让角色作出反应。二者发生在不同阶段。

开发期可以让 AI 帮助解释代码、起草角色行为或检查边界条件，开发者仍需核对引擎接口与实际效果。运行时 AI 根据游戏状态选择动作；简单 NPC 用规则和状态机就能完成巡逻、追逐，不必先训练模型。语言模型适合生成对话，但不能替代碰撞、导航和玩法规则。

本文以 Godot 中的单机 NPC 为示例路径，说明巡逻、追逐和对话如何配合。目录、状态和阈值均为示例设计，未创建工程或验证具体引擎版本。

# 项目结构

Godot 用节点树组织对象，保存的节点树可以成为场景，再被其他场景实例化；主场景是启动入口。[节点与场景](https://docs.godotengine.org/en/stable/getting_started/step_by_step/nodes_and_scenes.html)

下面是示意目录，不是已有工程清单：

```text
game/
├── scenes/
│   ├── World.tscn          # 地图、玩家与 NPC 实例
│   └── NPC.tscn            # 角色、感知区域和表现
├── scripts/
│   ├── npc_controller.gd   # 行为状态与移动协调
│   └── dialogue_client.gd  # 异步请求与响应分发
└── assets/                # 贴图、动画、音频源文件
```

## NPC

NPC 需要在玩家接近时触发对话。相关玩法约定见 [[NPC交互设计]]。

这里需要区分“进入可交谈范围”和“进入敌对感知范围”：前者用于发起交谈，后者用于发现追逐目标。两种范围可以重叠，但同一时刻应由统一控制器决定角色行为，避免对话脚本要求停止、追逐脚本又要求前进。

### 巡逻与追逐

示例使用 `PATROL`、`CHASE`、`TALK` 三个状态。巡逻时依次选择巡逻点；发现可追逐玩家后切换到追逐；连续一段时间失去目标后，回到可达的巡逻点。感知负责提供目标与可见性，状态机决定下一步目的，导航求出通往目标的路径，移动代码再处理实际位移和碰撞。

“看见玩家”不等于“能到达玩家”。目标在障碍物后或导航区域外时，应重新寻路或放弃目标，不能直接穿墙移动。失去目标的等待时间属于玩法参数，需要结合地图调整，而不是引擎的固定要求。

对话只在 NPC 可交谈且当前非追逐时开始；进入 `TALK` 后停止巡逻移动。示例约定受击优先级高于对话，受击会结束会话并切换到追逐；会话正常结束则恢复巡逻。具体敌对规则仍由 [[NPC交互设计]] 决定。

### 对话请求

把玩家输入发送到模型，得到回复后在游戏中显示。

实际需要同时带上 NPC 身份、允许公开的背景、当前会话编号与必要的任务状态。请求异步发送，等待时显示简短提示，游戏仍继续更新。超时或失败时显示预设台词，并允许退出；避免让网络等待冻结角色控制。

每次请求记录会话编号和请求编号。玩家离开、NPC 受击或会话结束时，把该会话标记为失效；即使无法取消远端计算，晚到回复也不能覆盖新会话。流式输出可在生成结束前显示文字，但不能保证整次生成立即完成。[生成延迟](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency)

#### 回复与游戏动作

自然语言回复只用于显示。若模型提出发放道具等动作，游戏代码必须检查玩家身份、任务完成条件、参数和重复领取状态。函数调用提供的是名称和参数，实际函数仍由应用执行并校验。[函数调用](https://ai.google.dev/gemini-api/docs/function-calling)

## World

世界场景提供巡逻点、障碍物、玩家位置与 NPC 实例。先让固定台词和简单场景跑通，再接入模型，有助于区分行为问题和网络问题。移动目标应来自地图中可达的位置；场景布局改变后，还需重新检查原巡逻路线。

# 运行与验证

检查玩家能否正常开始和结束对话。验证时还要覆盖状态变化，而不是只看能否显示一条回复。

| 操作 | 预期结果 |
| --- | --- |
| 玩家不进入感知范围 | NPC 按巡逻点移动，不重复发起请求 |
| 玩家进入敌对感知范围后绕到障碍物后 | NPC 追逐时绕开障碍；失去目标达到设定时间后返回巡逻 |
| 玩家进入交谈范围并结束会话 | NPC 停止巡逻，结束后恢复移动 |
| 回复返回前玩家离开或 NPC 受击 | 会话失效，旧回复不再显示 |
| 模型超时或重复提出领奖动作 | 显示回退台词；同一奖励不会重复发放 |

这些是验收预期，尚未运行。排查时记录状态切换、目标、会话编号及耗时即可定位大部分问题，日志中避免保存密钥与不必要的完整对话。
