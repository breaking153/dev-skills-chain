# 注释真实代码与精简表达

在已有主题与结构基础上，按以下要求重新生成 EDR 驱动层笔记与 AI 游戏开发试跑。

- 按总—分结构组织，合并属于同一机制的子标题；历史追问归类为知识，不逐题回答。
- 能通过实现解释的知识，以带注释的真实代码为主要载体，文字只交代前提、总述和代码没有表达的边界。
- 代码能简化就简化，不使用伪代码、虚构 API、孤立表达式或未实现的核心辅助函数；保留读懂控制流与参数流所需的上下文。
- 允许用 `// ...：省略日志格式化` 等注释省略非核心代码；关键条件、必需实参、状态变化、错误返回与必要清理仍须展开。含省略时标明“机制节选”，不能因此声称可直接编译运行。
- 回调示例在同一块代码中展示必要的入口参数、注册结构、注册调用、回调分派、结果与注销。无需展开完整工程或重复启动样板。
- EDR 的权限裁剪不能只剩 `DesiredAccess &= ~RightsToRemove`；应能追溯操作类型、权限字段、掩码与回调的绑定关系。
- 注册表通知类型与参数的对应优先放入真实 `switch` 和就近注释，不另写一张重复的枚举对照表。
- Mermaid 展示代码难以呈现的跨组件关系或时序，表格用于独立比较；同一事实不在代码、图表与正文中重复。
- 说明实际依赖和示例边界；不把未编译、未运行的片段写成已验证工程。

基础主题输入分别为 `edr-draft.md` 与 `ai-game-development.md`。EDR 采用 `/shuli`，AI 游戏开发采用 `/cdm` 的纯知识分支。
